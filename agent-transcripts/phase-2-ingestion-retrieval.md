# Phase 2 — Ingestion & retrieval

## What was built

- `ingestion/parser.py` -- parses `transcript.md` frontmatter + speaker turns.
- `ingestion/chunker.py` -- turn-aware chunker per the strategy in
  `docs/architecture.md` sec 2 (~300 words/chunk, never splits a turn, 1-turn
  overlap).
- `ingestion/ingest.py` -- clones/pulls the source repo, parses+chunks+embeds every
  episode, upserts into pgvector via idempotent `ON CONFLICT (episode_slug,
  chunk_index) DO UPDATE`.
- `apps/api/app/models_retrieval.py` + Alembic migration `a4f4b631a549` -- the
  `chunks` table, HNSW cosine index. Reviewed and hand-fixed the autogenerated
  migration (it referenced `pgvector.sqlalchemy.vector.VECTOR` without importing
  the module -- would have crashed on `alembic upgrade` for anyone who didn't
  happen to already have it imported elsewhere; added the import and the
  `CREATE EXTENSION IF NOT EXISTS vector` statement autogenerate doesn't know to
  produce, plus the HNSW index by hand since autogenerate only diffs plain
  columns/tables, not pgvector-specific index types).
- `apps/api/app/services/{embeddings,retrieval}.py` -- query-time embedding +
  cosine-similarity search with a relevance floor.
- `ingestion/scripts/verify_retrieval.py` -- the required standalone verification
  script (5 real questions, real retrieved chunks printed).

## Dead end #2: 29 episodes silently failed to parse on the first full ingestion run

First full run (303 episodes) reported `16021 chunks upserted across 274
episodes` and skipped 29 as `"no turns parsed"`. Investigated by opening the raw
files for several of the skipped episodes (`asha-sharma`, `melissa`,
`interview-q-compilation`, `gibson-biddle`, ...) instead of assuming they were
malformed.

**Root cause**: `docs/architecture.md` sec 1 (Phase 0) documented the timestamp
format as `Speaker (HH:MM:SS):` based on the one sample file inspected during
Phase 0 recon. That sample happened to be a >1-hour episode. Shorter episodes
(<1hr) use `Speaker (MM:SS):` instead -- **no hours component**. The Phase 0
regex (`\d{1,2}:\d{2}:\d{2}`) required exactly three colon-separated groups, so it
silently matched zero turns in every episode using the shorter format, and those
episodes fell through to the "no timestamp at all" fallback parser, which *also*
didn't match (because the lines really do have a `(MM:SS):` suffix, just not one
the fallback's "bare `Name:`" pattern expects either) -- hence "no turns parsed"
rather than a partial/garbled result. A quiet failure, not a loud one, which is
exactly why it wasn't caught until the actual full-corpus run instead of the
5-episode smoke test (the 5-episode sample didn't happen to include a short
episode).

**Fix**: `ingestion/parser.py` `TURN_MARKER_RE` changed from
`\d{1,2}:\d{2}:\d{2}` to `\d{1,2}(?::\d{2}){1,2}`, accepting both `MM:SS` and
`H(H):MM:SS`. `_hms_to_seconds` already zero-pads shorter timestamps correctly, so
no change needed there. Verified the fix directly against the four previously-
failing files before re-running full ingestion (parsed 123/35/64/145 turns
respectively, all with correctly-parsed `MM:SS`-style start timestamps) rather
than just re-running ingestion and hoping.

**Correction applied**: re-ran `python ingest.py` (idempotent upsert, safe to
re-run) against the full corpus a second time after the fix. See the ingestion log
tail below for the final real count.

**Lesson applied going forward**: Phase 0's format documentation was based on a
single sample file, which is exactly the kind of gap the assignment asks to be
honest about rather than silently ignore. Updated `docs/architecture.md` note is
already in place (parser.py docstring references this file); the actual
architecture.md doc itself intentionally does NOT get quietly rewritten to pretend
the format was fully understood from Phase 0 -- this log is the honest record of
when the fuller picture emerged.
